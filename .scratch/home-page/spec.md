# Главная страница для гостя

Status: ready-for-agent

Итог интервью (`/grill-with-docs`). Термины — по `GLOSSARY.md`.

## Решения

1. Главная страница `/` предназначена для гостя. Кабинет владельца остаётся на `/admin`; `/` больше не перенаправляет в кабинет.
2. Человек, который записывается, называется «гость» (не «посетитель»). Подтверждённая встреча называется «запись».
3. Один владелец без входа в систему (ADR-0001).
4. Типы встреч перечислены прямо на главной: каждая карточка показывает название, длительность, описание (обрезанное до 3 строк) и кнопку «Записаться», ведущую на ссылку для записи `/book/:slug`. Отдельной общей кнопки нет, slug в карточке не показывается.
5. В шапке главной — небольшая ссылка «Кабинет владельца» на `/admin`.
6. Минимальный лендинг: заголовок «Календарь звонков» и одна-две строки о записи на звонок без регистрации. Без блока «как это работает», отзывов и картинок.
7. Список типов встреч берётся из существующего `GET /api/event-types`; контракт не меняется (зафиксировано в ADR-0001).
8. Показываются все типы встреч в порядке создания, без проверки наличия слотов.
9. Пустое состояние: «Владелец пока не открыл запись.» Если сервер недоступен — сообщение об ошибке, как на остальных страницах.
10. Страница записи `/book/:slug` уже реализована, заглушка не нужна.

## Тесты

Шов: всё приложение, открытое на `/`, с подменённым API-клиентом. Проверяются карточки и ссылки на `/book/:slug`, переход на страницу записи, ссылка на кабинет, пустое состояние и ошибка.
