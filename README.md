## О проекте

Сервис позволит владельцу создавать типы встреч, настраивать доступное время и предоставлять посетителям ссылку для самостоятельной записи.

Основной референс проекта — [Cal.com](https://cal.com/). При изучении сервиса я рассмотрел основной сценарий: от создания типа встречи до появления новой записи в списке владельца.

## Пользовательский сценарий

1. **Создание типа встречи.** Владелец заходит в личный кабинет, открывает раздел типов встреч и создаёт новую встречу. Указывает название, описание и продолжительность, например «Консультация» на 30 минут. После сохранения для встречи формируется публичная ссылка.

2. **Настройка расписания.** Владелец задаёт дни и часы, когда готов проводить встречи. Например, с понедельника по пятницу с 09:00 до 17:00. На основании расписания система определяет доступные даты и время.

3. **Публикация ссылки.** Владелец копирует ссылку на созданный тип встречи и отправляет её посетителю.

4. **Выбор времени.** Посетитель открывает ссылку без регистрации, видит информацию о встрече, выбирает доступную дату и свободное время.

5. **Заполнение данных.** Посетитель указывает своё имя и email, проверяет информацию о встрече и подтверждает запись.

6. **Создание записи.** Система повторно проверяет доступность выбранного времени и создаёт запись, если слот свободен. Записи присваивается статус подтверждённой.

7. **Просмотр записи владельцем.** В личном кабинете владельца, в разделе записей, появляется новая встреча. Владелец видит название встречи, имя и email посетителя, дату, время и статус записи.

Таким образом, основной сценарий выглядит следующим образом:

**Создание типа встречи → настройка расписания → отправка ссылки → выбор свободного времени → заполнение формы → подтверждение записи → просмотр записи владельцем.**

## Основные правила работы

- Один владелец может создавать несколько типов встреч.
- Для каждого типа встречи задаётся своя продолжительность.
- Посетитель может записаться без регистрации.
- Доступное время формируется на основании расписания владельца.
- Уже занятое время не должно предлагаться другим посетителям.
- Перед созданием записи система должна повторно проверить доступность выбранного времени.
- После успешного бронирования запись появляется в списке встреч владельца.
- Изменение расписания не должно менять уже созданные записи.

## Стек

- Backend: Java, Spring Boot.
- Frontend: TypeScript, React, Vite.
- UI: Mantine.
- API: OpenAPI.
- База данных: PostgreSQL.
- Сборка backend: Maven.
- Тестирование: JUnit 5, Vitest.
- Линтеры: Checkstyle, Oxlint.
- Управление инструментами и задачами: mise.
- CI: GitHub Actions.

## Границы первой версии

На первом этапе планирую реализовать:

- Создание и редактирование типов встреч.
- Настройку рабочего расписания.
- Публичную страницу записи.
- Выбор свободных дат и времени.
- Создание записи посетителем без регистрации.
- Просмотр записей владельцем.

Пока не планирую реализовывать регистрацию посетителей, интеграции с Google Calendar и Outlook, уведомления, платежи, командные встречи и другие дополнительные возможности Cal.com.
